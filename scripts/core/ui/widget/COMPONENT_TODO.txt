blit camera revamp;   DONE
    currently;
        each blit happens to draw whether or not the entity or ui component is within the camera's view space
        strengths;
            it's fast
            easy to implement
            efficient
        weaknesses;
            hard to manage visibility
            has no logical way to determine if the object is fully contained or not due to the blits hierarchy
            cannot determine the exact space of objects to draw

    revamp;
        the camera revamp will guarantee the exact pixel space of the images sent to the blits callbacks
        by using the camera's position and size to determine the exact pixel bounds of the pyoneer objects
        and then only drawing the object's exact pixel bounds that are within the camera's view space
        strengths;
            easy to manage visibility
            can determine if the object is fully contained or not
            can determine the exact space of objects to draw

    X built as scripts/core/viewclip.py
        X containment(target, clip) -> OUTSIDE | PARTIAL | CONTAINED
        X clip_to_view(target, clip, source_origin) -> ClippedBlit | None
            returns the destination AND the source sub-rect already reduced to
            the pixels that land inside, or None when nothing does, so a caller
            culls and clips from one call and cannot do one without the other
        X wired into EntityLayer.core_render_blits   (clip = camera.view_area)
        X wired into DrawComponent.__blits            (clip = screen rect)
            the screen rect rides in the BLITS event beside "camera"; UI has no
            camera but has the same problem, which is why the primitive is a
            free function rather than a method on GameCamera
        X DrawComponent.last_containment answers "fully visible?" per component
        X BlitPool.count_culled() / .culled() so culling is observable rather
          than silent; tools/smoke.py reports blit_culled per frame

        measured on the shipped scene, window dragged off the left edge:
            before   63 tokens queued, 51 of them fully off-screen
            after    12 tokens queued,  0 off-screen, 51 culled
        on-screen the count fell 63 -> 59 with an IDENTICAL frame_hash: those
        4 were degenerate zero-area clips that drew nothing.

        NOTE the Z-axis half of this section was already solved by the blit
        pool's depth -> priority ordering; only the culling/containment half
        was still open. Verified by tools/check_viewclip.py.
