# Pyoneer

A 2D game engine built on [pygame](https://www.pygame.org/), with a separate
PySide6 editor for authoring maps, entities, event scripts and game data --
and for handing work to an AI in a form it can act on.

Three ideas hold it together:

- **Rendering is a sorted queue, not a stack of surfaces.** Nothing draws to
  the screen directly. Everything that draws pushes a token keyed by depth and
  priority, and the renderer flattens the frame into one `surface.blits()`
  call. A frame is data before it is pixels, which is why the regression
  harness compares token histograms instead of screenshots.
- **An entity is one class carrying a list.** A map object names its
  behaviors (`player_input,topdown_move,animation_drive`), and they are
  attached when it spawns. A top-down hero, a platformer body and a scripted
  patrol are the same class with different lists: genre lives in map data.
- **Every edit is a command that returns its own undo.** A click on the
  canvas, a cell typed into a table and a line an AI writes back all become
  the same kind of object, so the undo stack is a readable list of verbs.

This is a personal engine being cleaned up in public, not a released library.
Names still move; pin a commit if you build on it.

## Running the game

```bash
git clone https://github.com/AbstractEyes/pyoneer-engine
cd pyoneer-engine
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # pygame, pytmx
.venv/Scripts/python.exe main.py
```

No install step and no `PYTHONPATH`. It boots `data/maps/starter.tmx`, and
everything in the world comes from that map.

Controls: **WASD** move, **Ctrl** sprint, **E** interact, **F1** toggles the
debug window, **Esc** quits. Press **E**: a chime plays, a dialogue box
opens, and steering is held until the conversation ends. That is an event
script attached to the hero's map object, not code in `main.py`. Bindings
live in `config/inputs.json`; a typo raises instead of binding nothing.

Art and audio ship. The art under `data/art/` is generated by `tools/art/`;
the two sounds under `data/audio/` are free to redistribute. Drop your own
files under `data/graphics/` or `data/sound/` (both untracked) and they win
over the shipped ones. [`docs/ASSETS.md`](docs/ASSETS.md) has the details.

Tracing is opt-in per subsystem and free when off:
`PYONEER_DEBUG=mouse,events,render` (or `all`). An unknown channel raises.

## Running the editor

```bash
.venv/Scripts/python.exe -m pip install -r editor/requirements.txt   # PySide6
.venv/Scripts/python.exe editor/app.py
```

The editor is a separate process: **File > Play the game** (F5) saves, then
launches `main.py`. `editor/` may import the engine, never the reverse, so the
game runs on a clone with the editor deleted.

## What you can do today

**Maps.** Maps are [Tiled](https://www.mapeditor.org/) `.tmx` files. pytmx
reads them and cannot write them, so `scripts/loaders/map_document.py` is a
reader/writer that round-trips a file byte for byte: load and save changes
nothing, and add-then-remove of an object, layer or tileset gives back the
original bytes, so Tiled and a script can edit the same file.

```python
doc = MapDocument.load("data/maps/starter.tmx")
doc.tile_layer("Floor").set_tile(4, 7, gid=65)
doc.object_layer("entity").add_object(name="guard", type="GamePlayer", x=128, y=96)
doc.save()
```

`GamePlayer` is the only type that spawns; the generated list of what can be
placed is [`docs/PLACEABLE.md`](docs/PLACEABLE.md). There is also a native
plain-text format (`.blitmap` / `.tileset`) with a lossless converter from
`.tmx`. It does not carry collision yet.

**Tilesets and collision.** The palette shows every tileset in the map. You
can build a tileset from any rectangle of any image, grow it by rows, and
rename it. Collision is a brush: masks go on individual tiles in the palette
(so stamping a wall also stamps its collision) or on single map cells where
one cell needs to differ. [`docs/TILESETS.md`](docs/TILESETS.md) covers all
of it.

**Behaviors.** An object's `pyoneer_behaviors` list decides what it becomes:
driven by input, moved top-down or side-on with gravity, animated, firing
actions. Parameters come from `pyoneer_param_<key>` on the object or from a
row in `data/project/tables/`. Genre packs give each new object a starting
list. Registry, run order and which tokens are actually wired:
[`docs/BEHAVIORS.md`](docs/BEHAVIORS.md).

**Event scripts.** A script is a JSON document under `data/project/scripts/`:
pages with triggers and conditions, and nodes that `say`, `set` variables,
`hold` and `release` the player's steering, `wait`, `call` other scripts, and
play sounds or music. `pyoneer_script` on a map object attaches one to the
spawned body, and the `action` verb runs it. The editor's event screen
(`editor/ui/script_editor.py`) edits scripts as structured pages rather than
raw JSON, and the object editor (`editor/ui/object_editor.py`) shows one
entity's placement, behaviors, parameters and actor row on one screen. The op
vocabulary and what each op needs is [`docs/EVENTS.md`](docs/EVENTS.md).

**Audio.** `play_sound` and `play_music` resolve a name like `sfx/chime.wav`
against `data/sound/` first, then `data/audio/`. No sound card gives one
warning and silent no-ops; a missing file raises, even on a silent machine.
Licences for what ships: [`data/audio/CREDITS.md`](data/audio/CREDITS.md).

**The relay.** Every editor panel has a prompt strip that knows its scope
(`map:starter/layer:Floor`, `table:actors/row:hero`). A note typed there is
addressed to that scope. Shipping notes writes a request bundle for an AI --
a brief, the genre pack's rules, the live state of each scope, the notes, and
a command vocabulary generated from the registry that executes it. The AI
answers with commands, and a response is applied as one transaction: an
unknown verb or a wrong type rejects the whole thing, and nothing is ever
half-applied. Design and reasoning:
[`docs/PLAN_EDITOR.md`](docs/PLAN_EDITOR.md).

**Demos and new games.** Four prototype games under `demos/` (top-down,
side-on platformer, a scripted patrol, a cutscene) are each a map plus a
class of a few lines: [`docs/DEMOS.md`](docs/DEMOS.md). To make your own, fill
in the one-screen form in [`docs/DESIGN_TEMPLATE.md`](docs/DESIGN_TEMPLATE.md),
which a check resolves against the live engine, then follow its design, build,
prove loop.

## How rendering works

```
  entity / widget / map layer
        │  core_render_blits(event)
        ▼
  BlitPool.blit_to_layer(depth, priority, image, destination, draw_area)
        │
        ▼
  ORGANIZED_BLITS[depth][priority] → [BlitToken, ...]
        │  flattened depth → priority → insertion order
        ▼
  surface.blits(...)          ← one call, once per frame
```

- **Draw order is an integer, not a tree position.** A widget nested five deep
  can draw beneath the map. Depth accumulates through the parent chain, so a
  subtree moves together.
- **Culling and clipping are one operation.** `clip_to_view` in
  `scripts/core/viewclip.py` returns the destination and the visible source
  rectangle together, or `None`, so the two cannot drift apart.
- **Static map layers are composited** only where `composite_is_exact()`
  proves the merge is lossless, and `renderer.invalidate()` /
  `rebake_map()` keep live map editing possible.

One trap before subclassing: the `core_<domain>_<action>` methods
(`core_frame_update`, `core_render_blits`, ...) are entry points for objects
driven from outside the component graph: scenes, layers, entities. A
component reached through its parent is driven by the event bus, which never
calls them, so an override there silently does nothing. Register a listener
instead: `self.bind_sync_listener(GameEventType.UPDATE, self.__on_update)`.

## Layout

```
main.py                     entry point: boots the shipped map
config/                     JSON: animations, audio, entities, inputs, maps, theme
data/maps/starter.tmx       the shipped map
data/art/  data/audio/      shipped generated art, shipped sounds (+ CREDITS.md)
data/project/               tables, event scripts, scene variables
scripts/core/               engine: blit queue, renderer, events, input, spawn
  audio.py                    the two sound roots, and card-vs-file failures
  scene/  ui/                 scene graph; widgets and containers
scripts/game/               entities, behaviors, camera, map
  flow/                       event-script ops and interpreter, scene flow, action router
scripts/loaders/            no pygame, no Qt: files on disk <-> plain Python
  map_document.py             byte-faithful TMX read/write
  script_file.py              event-script documents
  table_file.py               data/project/tables/
editor/                     the authoring application (PySide6, separate process)
  core/                       headless: commands, verbs, scopes, genres, relay
  ui/                         Qt panels, including script_editor.py and object_editor.py
  genres/                     genre packs: topdown_rpg, platformer
demos/                      four prototype games
tools/                      checks, the smoke harness, art generation
docs/                       guides and generated references (see above)
```

## Running the checks

```bash
.venv/Scripts/python.exe tools/check_all.py
```

One command, one exit code: every check plus a frame-drift comparison. The
checks are not unit tests. Each one boots or drives real engine code and
asserts measured behaviour: token counts, dispatch counts, frame hashes,
pixel equality. The roster, with one line per check, is
[`docs/CHECKS.md`](docs/CHECKS.md).

`tools/smoke.py --frames 60` runs the game headless and reports a frame hash,
the blit-token histogram and listener calls per frame. It presses no keys, so
"no drift" never means "nothing changed".

## Contributing

The bar is measurement: this codebase has a documented history of plausible,
wrong claims, including in its own docs. Before changing anything, read the
hard laws in [`CLAUDE.md`](CLAUDE.md). They are short, and each one records
what breaking it cost. In brief: run `tools/check_all.py` before and after,
prefer a raise to a fallback, and make every check able to fail by breaking
the code it covers and watching it go red.
